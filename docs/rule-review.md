# 除外ルールの毎日の見直し（深夜の自動セッション用の手順）

PR Times Watcher の利用者が「不要」にした記事と、その理由（自由記入・選択肢）、自動除外から受信箱に戻した記録をもとに、
`src/lib/exclusion.ts` の自動除外ルールを見直す。毎日深夜に自動で実行される。

## 守ること
- 利用者は1人（i-kato@spark-partners.jp）。読みたい記事を除外してしまう方が、不要な記事が残るより悪い。迷ったら足さない。
- **同じ種類の理由が3件以上**たまったときだけ、新しいルールにする。2件以下なら見送り、次の回に持ち越す。
- ルールは基本 `titleRule()`（タイトルの正規表現）で作り、`except` に `ALWAYS_KEEP`（資金調達・上場・M&A など）を必ず含める。
- 既存のルールの `id` は変えない・使い回さない（画面のオン・オフ設定が id で保存されている）。
- ルールで除外された記事を利用者が受信箱に戻した記録が **2件以上** あるルールは、例外を足して直す。直せなければそのルールを外す（配列から消す。id は再利用しない）。
- このファイル・`src/lib/exclusion.ts`・`src/lib/exclusion.test.ts`・`docs/rule-review-log.md` 以外は変えない。不具合を見つけたら直さず、報告に書く。
- 秘密情報（APIキーなど）は扱わない。データを書き換える操作（Firestore への書き込み・削除）はしない。

## 手順
1. リポジトリ `ItaruKato/prtimes-inbox` を用意する（セッションに無ければ add_repo で push 権限付きで追加し、clone する）。
   `git config user.name Claude` / `git config user.email noreply@anthropic.com` を設定する。
2. 本番の健康診断を実行し、見直しの材料を読む。
   ```bash
   gh workflow run health.yml --repo ItaruKato/prtimes-inbox --ref main
   # 終わるのを待ってからログを読む（「不要にした理由」「戻した記録」「理由なしで不要にした記事」の節）
   gh run view --repo ItaruKato/prtimes-inbox <run id> --log
   ```
3. `docs/rule-review-log.md` の「処理済みの最終時刻」より新しい材料だけを対象にする（`at` はミリ秒）。
   健康診断の出力に `at` が無い場合は、ログに記録済みのタイトルと照らして新しいものを判断する。
4. 材料を種類ごとにまとめる。理由の選択肢（reasonTags）が同じもの、自由記入の内容が似ているもの、タイトルの言い回しが共通するもの。
5. 3件以上たまった種類があれば、ルール案（タイトルの正規表現と例外）を作り、本番の全記事で試す。
   ```bash
   gh workflow run rule-check.yml --repo ItaruKato/prtimes-inbox --ref main -f pattern='<正規表現>' -f except='<例外の正規表現>'
   ```
   - 「読む」「既読」に入れた記事・受信箱に戻した記事に当てはまる件数が **0件** であること。
   - 除外される記事の例を最後まで読み、読みたい記事（新規事業・提携・マーケティングの具体的な取り組みなど）が混ざっていないこと。混ざっていれば例外を足して試し直す。
   - 全記事に対する除外の割合が大きすぎる（目安15%超）ルールは、範囲を絞る。
6. ルールを `src/lib/exclusion.ts` の `EXCLUSION_RULES` に足し、`src/lib/exclusion.test.ts` の `CASES` に
   実際のタイトルで「除外する例」「除外しない例」を3件以上ずつ足す。`npm ci && npm test && npm run build` が通ること。
7. `docs/rule-review-log.md` に、日付・材料の件数・作った／直したルールと根拠（理由の件数と例）・試し判定の結果・見送った種類を書き、
   「処理済みの最終時刻」を更新する。何も変えなかった日も1行残す。
8. 変更があれば main に commit して push する（デプロイは自動）。デプロイの成功を確認する。
9. 最後に、利用者向けの短い報告を日本語で書く（変えたルール・除外されるようになった件数の目安・止め方は「不要」画面のルール一覧のチェックを外す）。
   何も変えなかった日は「材料が足りず見送り（理由○件）」とだけ書く。
